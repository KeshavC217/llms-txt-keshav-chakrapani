1. Built the llms.txt from the single fetched page only — `lib/llmsTxt.ts` pulls the title/description, the same-site links as subpages, and the page's own text, and `/api/generate` now returns that rendered template instead of the raw body.
2. Made the GitHub repo public after checking the full history for committed secrets (only `.env.example` was ever tracked, no secret-shaped strings), which also unlocks branch protection on the free plan.
3. Wired up merge → deploy: added a lint/typecheck CI workflow, protected `main` behind a passing `ci` check, and shipped the generator through PR #1 — fixing a pre-existing `npm ci` lockfile break along the way — then confirmed the merge deployed to production.
4. Defined `TEMPLATE.txt` — the target llms.txt skeleton, generalized from the llmstxt.org spec plus a 22-file sample from llmstxt.site, fixing the structure and slot rules while leaving section vocabulary site-derived.
5. Built a naive extractor against TEMPLATE.txt — a small HTML tree (`lib/dom.ts`), text utilities (`lib/nlp.ts`) and `lib/naiveExtractor.ts`, which uses link density to drop boilerplate, path segments plus nav headings to name sections, token overlap to dedupe titles and reject notes that restate their link, and caps to keep the file curated.
6. Made spec conformance enforced rather than claimed — `lib/spec.ts` implements the llmstxt.org grammar in both directions (escaping on output, parsing to verify), every response reports validity, and `npm run conformance` runs the spec's own example, six must-reject files and eight hostile pages in CI.
7. Added a zero-dependency unit suite on node:test (59 tests over nlp, dom, spec and the extractor, with mock pages per site genre), which found and fixed five real defects including an implicit-close table keyed backwards in the HTML parser.
8. Integrated Supabase email/password auth — session refresh in `proxy.ts` (Next 16's replacement for middleware), a verified `getUser()` check, and `lib/authGate.ts` gating the LLM path so the generator stays open to everyone while AI features require an account.
9. Fixed a false "application shell" claim — client rendering now needs positive evidence (a script plus an empty mount element) rather than being inferred from the absence of links, which was equally true of small complete pages like example.com.
10. Added the AI sieve — a guide pass for the summary and section names, chunked annotation for per-link notes, and acceptance filters that drop anything a model invents, with the deterministic file served whenever the result would be worse or invalid.
11. Told model failures apart — retry with jittered backoff on 429s and 5xx (honouring Retry-After), stop immediately on 402/401 and answer 503, and report failures by kind, which surfaced a deadline truncating chunks and led to a wider budget.
12. Added an end-to-end evaluation that samples sites publishing their own llms.txt, generates both our outputs and has a cheap model grade each against the published file — showing the AI sieve gains on descriptions and structure while coverage stays at the noise floor, as it must.
13. Taught the fetcher to tell refusals apart — a browser-identity retry when a site merely dislikes our agent (zillow: 403 to 99 links), explicit detection of anti-bot challenges instead of generating a file about Cloudflare, and an optional remote-browser render for pages whose links only exist after JavaScript.
13b. Removed the browser-identity retry after failing to validate it — zillow's 403 turned out to track HTTP client and address reputation rather than the User-Agent, so the swap was shipping an impersonation with no demonstrated benefit.
14. Stored AI-assisted generations globally in Supabase behind the secret key — the enhance endpoint serves a fresh one without touching the site or the models (28.8s to 0.6s), and degrades to plain generation when the table or key is absent.
15. Added a crawler — the site's own llms.txt when it publishes one, otherwise sitemap and link discovery paced by what the site tolerates, honouring robots.txt, with each page's own title and description replacing names guessed from slugs.
16. Made the crawl deterministic — pages are planned before any fetch and results sorted back into plan order, so the same site yields byte-identical output and a content hash can mean the site changed rather than that a packet was slow.
17. Added the updater — a scheduled re-check that compares a model-free fingerprint of the site, escalating from sitemap to crawl to regeneration only as far as needed, with each site's interval following how often it actually changes.
18. Raised monitoring throughput — sites are checked four at a time rather than one, which took thirteen checks from 46 seconds to 11, and the schedule moved to every five minutes offset off the hour, where GitHub says load is highest.
19. Moved the queue loop into the GitHub runner, which has six hours where a function has sixty seconds, while leaving the crawling on the deployment so no credentials reach CI and requests keep the app's own address rather than a shared one.
20. Simplified the model — one endpoint that always crawls, always runs the models and always saves, generating behind an account while reading stays open to anyone, and the AI toggle and the four conditions on saving are gone.
21. Saved the site's own llms.txt too, labelled as theirs rather than ours, and taught the scheduled check to re-read a published file instead of crawling and replacing their curation with our generated version.
22. Made the documentation describe the program that exists — the README still said the tool fetched one page and did not crawl, documented an `/api/enhance` removed two PRs earlier, and pointed at a tag as the "full implementation"; added the schema as `db/schema.sql` and the automated-updates story the README had never told, re-measured the output against published files now that there is one endpoint to grade rather than two (8.69/15, judge noise 0.63), repaired `npm run integration` which had been calling the deleted endpoint, and deleted three pieces of dead code the prose was still describing as live.
